Bài toán & mục tiêu

Vấn đề

  • Hàng lạnh hỏng nếu vượt ngưỡng nhiệt khi vận chuyển.
  • Thiết bị đo có thể bị giả mạo.
  • Dữ liệu lịch sử có thể bị sửa trong DB để che vi phạm.
  • Request cũ có thể bị replay.

Mục tiêu

  • Thu thập nhiệt độ, độ ẩm, GPS mỗi 10 giây.
  • Chỉ nhận dữ liệu từ thiết bị đã xác thực.
  • Phát hiện mọi hành vi sửa / xóa dữ liệu.
  • Dashboard giám sát realtime + mô phỏng lộ trình 3D.

Luồng giao tiếp — 3 giai đoạn

GĐ 1 · Chuẩn bị
Admin→Backend: POST /api/admin/devices/generate-code — sinh mã kích hoạt (kèm QR)
GĐ 2 · Provisioning
(một lần)
ESP32→Backend: POST /api/devices/verify — gửi public key + verify code
Backend←trả api_key đúng 1 lần; DB chỉ lưu HMAC(api_key)
ESP32→Backend: POST /api/devices/bind — quét QR gắn đơn ship (đổi được nhiều lần)
GĐ 3 · Vận hành
(mỗi 10 giây)
ESP32→Backend: POST /api/telemetry — body JSON + headers X-Signature, X-Nonce, X-Timestamp
Backend←verify chữ ký → lưu vào hash chain → sinh cảnh báo nếu vượt ngưỡng
Dashboard→Backend: GET /api/shipments/{code}/telemetry, /alerts — poll mỗi 5 giây

Lớp 2 — Chống replay & chống sửa đổi

Mỗi bản ghi móc vào bản ghi trước bằng HMAC — sửa 1 dòng làm lệch cả chuỗi phía sau.

Bản ghi #1

payload_hash
signature
record_hash₁

→prev = hash₁
Bản ghi #2

payload_hash
signature
record_hash₂

→prev = hash₂
Bản ghi #3 (bị sửa)

hash tính lại ≠ hash lưu
⚠ tampered

→lệch dây chuyền
Bản ghi #4…

previous_hash không khớp
⚠ cả đuôi chuỗi lệch

Điểm đối soát (integrity anchor)Head hash công bố định kỳ ra sổ append-only + file ngoài DB → xóa cả chuỗi cũng bị phát hiện. Khóa HMAC nằm ngoài DB.

Chống replay

  • Timestamp lệch > 5 phút → từ chối · nonce dùng 1 lần → gửi lại request cũ bị chặn.

Demo phản chứng

  • Sửa 1 dòng trong PostgreSQL → màn Toàn vẹn & Giám sát lập tức tô đỏ ⚠ "Đã sửa".
